# مزرعتي · الطبيب والوكيل | Mazraa Agent

تطبيق Flutter مستقل للطبيب البيطري والوكيل التجاري، مرتبط بالسيرفر الحالي `https://mzraa.runasp.net`.
يدعم العربية وRTL والإنجليزية، المظهر الفاتح والداكن والنظام، و92 شاشة ونافذة من خطة التطبيق.

## استخراج التطبيق

[افتح أكشن الاستخراج](https://github.com/naba125555-ui/mazraa_agent/actions/workflows/extract-agent-arm64.yml)، ثم اختر **Run workflow → main**.
بعد النجاح حمّل **mazraa-agent-arm64** من Artifacts، وفك الضغط وثبّت `app-arm64-v8a-release.apk`.

يوجد أكشن واحد فقط. لا يُشغل مع تعديلات الشيفرة العادية. ملف `.build/extract-once` مخصص لاستخراج الإصدار الأول بعد اكتمال التطوير؛ بعده استخدم التشغيل اليدوي.
يبني Release لمعمارية ARM64 فقط، مع R8 وتقليل الموارد والأيقونات وضغط المكتبات الأصلية وفصل رموز التصحيح.
تُستعاد ذاكرة Flutter/Pub/Gradle المؤقتة ويُستخدم Java 17 المثبت؛ أول تشغيل يحتاج تنزيل ما لم يُخزن بعد.
رموز الأعطال ومعاينات الثيمين وملف قفل الاعتماديات موجودة في **mazraa-agent-verification**.

## أربع طبقات

| المجلد | المسؤولية | الاعتماد المسموح |
|---|---|---|
| `lib/domain` | النماذج، الصلاحيات، واجهات المستودع، فهرس الشاشات | Dart فقط |
| `lib/application` | الجلسة التشغيلية، سياق العمل، الأوامر، المسودات، العقود | domain |
| `lib/data` | HTTP، تجديد الرموز، التخزين الآمن، الملفات | domain |
| `lib/presentation` | الواجهات، الثيم، التنقل، الرسوم البيانية | application وdomain |

`lib/main.dart` هو نقطة تركيب الاعتماديات. يفحص `tool/check_structure.py` اتجاه الاعتماد وفهرس المسارات والأصول وXML.

## الأصول والهوية

كل الأصول محلية في `assets/`: شعار العميل، خط Cairo مع ترخيصه، الزخارف النباتية وشعار SVG من السائق، وصورة اللقاح من العميل.
أُعيد استخدام الأصول الأصلية، ولم تُستخدم صور الشاشات كواجهات.
الألوان: أخضر `#155A37`، عاجي `#FCFAF2`، برتقالي `#C76532`، خلفية داكنة `#0D1510`، بطاقات `#17231B`، نعناعي `#83C99E`.
الأيقونة الأصلية نفسها مستخدمة في Android. الرسوم البيانية مرسومة كمتجهات وتعرض القيم نصيًا أيضًا.

## التشغيل والاختبار

استخدم Flutter **3.47.8** وJava 17 وAndroid SDK الموافق لـFlutter.

```bash
bash tool/prepare_android.sh
flutter pub get
python3 tool/check_structure.py
flutter analyze --no-fatal-infos
flutter test
flutter run
```

على Windows عند غياب Gradle wrapper:

```powershell
flutter create --no-pub --platforms=android --org com.mazraa --project-name mazraa_agent .
flutter pub get
flutter run
```

يمكن تغيير عنوان بيئة الاختبار عبر `--dart-define=API_BASE_URL=https://your-api.example`؛ لا تضع الأسرار في المستودع.
المعمارية لا تستدعي الحسابات الإدارية نيابة عن الطبيب؛ يلزم حساب مُعتمد وتفويض مخزن وصندوق بالقدرات المطلوبة من الإدارة.

## حدود التشغيل المقصودة

- بيانات الواجهات الحية تأتي من السيرفر. البيانات الاصطناعية موجودة في `test/` فقط.
- الحساب المهني تديره الإدارة؛ استعادة كلمة المرور لا تتظاهر بوجود مسار استعادة عام غير موجود.
- حيوان الحالة مرتبط بإحالة العميل. لا ينشئ الطبيب حيوانًا باسم عميل آخر عبر مسار الملكية القديم.
- الصرف يتطلب الترخيص المستقل والتفويض والدفعة والوصفة الصالحة. صرف النقد والتسليم لا يُعتمدان دون تأكيد خادمي.
- النقد/المرتجعات/المزاد تستخدم الحالة والإصدار اللذين يعيدهما السيرفر؛ المراجعة المستقلة تظل لدى المخوّل بالإدارة.
- الملاحظات المحلية مشفرة ومعزولة بالحساب ولها مدة 24 ساعة. العمليات المالية غير المؤكدة تحتفظ بنفس UUID والحمولة عند إعادة المحاولة.
- تعمل المحادثة بتحديث REST كل 5 ثوان في المقدمة، وتُحدّث الصلاحيات والسياق كل 30 ثانية وعند العودة للتطبيق. لا يتطلب التشغيل Firebase. وصول Push والتطبيق مغلق يحتاج إعداد مزود الإشعارات وجهازه بصورة منفصلة؛ لا يُدّعى تفعيله هنا.
- الملاحة تُفتح في تطبيق الخرائط الخارجي من العنوان أو الإحداثيات الفعلية. إذن الموقع مطلوب عند توثيق الوصول فقط.
- قراءات API القديمة، مثل حركات المخزون، قد تحتاج إذن القراءة الإضافي الموجود في السيرفر؛ تظهر حالة وصول واضحة إذا لم يُمنح.
- توقيع النسخة الافتراضية هو توقيع تطوير محفوظ في cache. للتوزيع الرسمي استخدم `android/key.properties` ومفتاحك الخاص خارج git.
